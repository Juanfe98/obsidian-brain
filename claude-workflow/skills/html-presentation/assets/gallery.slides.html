Where we are today

Two apps ship automatically. Two still need a person with Azure access.

Pause here. Give people a beat before the detail starts.

A green build on main does not mean the change is deployed.

For the catalog API, CI runs on every push, but the deploy job is skipped until one variable is set.

This is the key message. Say it, then stay quiet for two seconds.

Why it matters

Manual deploys cost us more than time

  • Only two people can ship Everyone else waits for them, even for one-line fixes.
  • What runs in DEV is hard to trace Images built by hand are not tied to a commit we can check.
  • Steps get skipped under pressure Smoke checks like /ready only happen when someone remembers.

One point per click. Give an example from last sprint for the first one.

The gate

One condition decides whether we deploy

The deploy job runs on pushes to main, but only when the Azure client ID variable is set.

The variable is empty today, so the job is skipped on every run.

Point at the highlighted line. That empty variable is the whole story.

The pipeline

Three stages, each with one job

🧪

Verify

Typecheck, lint, unit tests and the OpenAPI contract check on every pull request.

📦

Package

Build one image per commit, tagged with the short SHA, pushed to the registry.

🚀

Release

Point the App Service at that exact tag, restart, then smoke-check /ready.

Stress that the image tag is the commit SHA, never latest.
