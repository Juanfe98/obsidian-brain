# Verify and repair

Validate the input, inspect the actual delivered artifacts, and review every native page.
Automated checks and visual acceptance answer different questions; neither replaces the other.

## T0 — no browser (`validate`)

Schema, per-layout slot contracts and reconstructed theme contrast floors. Narrative guidance
is reported separately and never blocks a single slide or an appendix.
Every message names the field and the overage, so the fix is mechanical:

```
slides[4].takeaway is 118 chars, 8 over the 110 limit
```

## T1 — reconstructed HTML probe (`build --reconstruct`)

One `page.evaluate` in a real 1920x1080 Chromium. Each rule replaces a naive check that was
measured to miss real defects — do not "simplify" them back:

| Rule | Severity | Why the obvious check fails |
|---|---|---|
| `text-clipped`, `text-overflow` | blocker | `scrollHeight - clientHeight` returns **0** on a fixed-height `overflow:visible` box that is spilling text. Range ink measurement catches it. |
| `text-truncated` | blocker | ellipsis is an X-axis fact; a Y-only check passes every truncated headline |
| `off-canvas`, `outside-safe-area` | blocker / high | 44px margin, brand-derived (not EBU's 96px, which would flag the official template) |
| `low-contrast` | high | composites the **ancestor** background chain; an element's own `background-color` is `rgba(0,0,0,0)` and would compute against black |
| `undersized-text` | high | 36px prose floor, 20px for marked secondary furniture |
| `font-substituted`, `webfont-failed` | high / blocker | `document.fonts.status` reports `loaded` while the only FontFace is `error`; `document.fonts.check()` returns **true** for absent families. Canvas width vs a sentinel is the only reliable probe. |
| `image-aspect-distorted` | high | gated on `object-fit: fill\|none`; `cover`/`contain` do not distort |
| `opaque-overlap` | blocker / medium | `document.elementFromPoint` answers who paints; `z-index` strings are per-stacking-context and usually `auto` |
| `off-grid` | nit | modular distance to the nearest gridline; `v % grid` reports a 7px error one pixel *before* a gridline |
| `widow-line` | nit | last-line width and word count from real line boxes |
| `off-brand-color` | medium | any color outside the theme palette |

Plus a **scale-differential** pass: the same deck is measured at deviceScaleFactor 1 and 2 and
the normalized geometry must be identical. Any difference is a unit bug in the generated CSS.
One extra render, no image comparison.

## T2 — current native artifacts

"It opens" proves nothing: pptxgenjs emits chart XML that python-pptx reads, LibreOffice
renders, the XSD passes — and PowerPoint refuses.

**Native PDF:** rendered from the emitted PPTX by PowerPoint/Keynote/LibreOffice, or exported
by Google from the copied presentation. Chromium rasterizes these actual PDF pages; it does
not reconstruct a native deck. The page count and 1920×1080pt size must match. Planned text must
be present in the rendered text and remain inside the canvas. Inspect slot clipping, overlap
and font fidelity visually; text extraction alone cannot detect every covered or overflowing
object. Approved source Arial is valid. Reconstructed output separately checks its Avenir faces.

Native list markers are generated by Google and may appear between authored
paragraphs in PDF extraction. Verification requires every authored paragraph in
order, including its punctuation, while allowing generated markers between them.
It still rejects missing or reordered paragraphs. Inspect dense lists for footer
collisions even when all their text is present in the PDF.

Read-only Google source previews are reference evidence, separate from delivered-deck export
verification. Compare the selected official source pages with final native output. Mask only
the intentionally edited content and changing slide number when checking unchanged pixels;
keep logos, backgrounds and unedited artwork in scope. Verify the source master/layout objects
as well. A pixel match outside those masks does not grade the edited content's meaning or fit.

**PPTX (zip-level):** `sldSz` == `24384000 x 13716000` EMU · `<p:sp>` count > 0 and `<a:t>` runs
exist (zero runs means every slide is an image) · `<p:pic>` occurrences equal declared image
uses while `ppt/media/` equals unique image bytes · every IR string appears on its expected
slide in one text body's `<a:t>` text · each expected chart appears on its expected slide with
the declared type, series names, categories, and values · `srgbClr` values are 6 hex digits · no
`dLblPos="outEnd"` on a stacked bar · each cartesian `<c:*Chart>` group resolves its declared
axis parts (fewer and PowerPoint silently discards the chart).

The text comparison is on **decoded** character data, not raw markup. A claim like
`latency < 50ms` is correctly stored as `latency &lt; 50ms`, so matching the IR against raw
`<a:t>` bytes reported a false `pptx-missing-text` blocker. Runs are rejoined per text body with
no separator (pptxgenjs splits values mid-word across `<a:r>`), and bodies stay separate so two
unrelated text boxes cannot jointly "contain" a string neither one shows. Decoding lives in
`scripts/lib/ooxml.mjs` (`decodeXmlText`, `slideTextBlocks`) — dependency-free, so the hermetic
suite can test it without `node_modules`.

## T3 — bounded visual critique

Inspect the actual native thumbnails. A build report retains `fidelity.status: requires-visual-review`
even when automated checks pass.

```sh
node <skill-dir>/scripts/deck.mjs thumbs build/<slug>      # PNG per slide
```

Then **read every PNG** beside the matching source design in the same application. Check
font family/weight, wrapping, geometry, logo, footer, timeline markers, chart labels and image
crops. Confirm native text, table cells and chart data remain editable in the destination.

Report only what the DOM cannot express: visual hierarchy, crowding, emphasis, whether a chart
actually communicates its takeaway, whether the palette feels chosen for *this* topic. Describe
the **problem, not the prescription** ("the three metrics read as unequal", not "set 72px").

Fix the observed issues together and repeat the affected checks. Do not declare pixel fidelity
while any visible mismatch or untested destination remains.

These were all found by looking, after every rule passed:

- a line chart flattened to a dead horizontal rule (axis forced to zero)
- three peer metrics at 180px/72px/72px, reading as a mistake
- a value slot rendering in ink instead of accent
- a timeline axis dangling past the last milestone
- an "axis starts at" / "axis ends at" note clipped by the plot box

## Repair

Overflow means **too many words**, not too large a type size. Cut content or move it to another
slide. Reconstructed output disables shrink-to-fit; native output retains source behavior. Always
inspect the actual target for unwanted autofit or clipped text.

If a slot needs more room, choose a compatible source layout. After two unsuccessful review
passes, reconsider the layout or split/shorten the content while preserving its facts, then
render and review again. Keep unresolved defects on the repair list and complete them before
presenting the deck as finished. Editing a milestone's date label does not require moving its
native timeline markers; check related dates throughout the deck after the edit.

## Fresh verification and regression evidence

`verify <dir>` rehashes every delivered file from `.verify/integrity.json`, then reopens the PDF
and PPTX. A changed, missing, corrupt or escaping file fails even if `report.json` says the old
build succeeded. Hashes bind input/template provenance and native rendering to the delivered
bytes. This is local integrity evidence, not a digital signature or proof against deliberate
replacement of the report and manifest together.

Hermetic regressions cover native request planning, Unicode indices, styles, table edits,
independent repeated chart workbooks, missing capabilities, copy drift, ambiguous writes,
current-file corruption and XML attribute ordering. Property tests exercise parser/order/text
invariants. Run `npm ci --install-links` in `scripts`, then `node --test`.

For a realistic live exercise, author matching light and dark operating reviews
with repeated organizational diagrams, grouped process labels, four- and six-stop
timelines, merged table captions, dense scorecards, varied text styles and image
replacement. After building, edit and restore a native table cell and diagram
label, reject a stale revision without mutation, compare source fingerprints, and
verify fresh exports. Compare effective text styles through layout/master
inheritance: Google can remove redundant overrides and round transform values
without changing the rendering. Image replacement can change intrinsic size and
transform while retaining the same displayed frame.

Optional integration checks use `DECK_BROWSER_TESTS=1`, `DEE_TEMPLATE_LIGHT` and
`DEE_TEMPLATE_DARK` to test actual browser/native artifacts. Keep these authorized files outside
Git. Live Google checks require an authenticated account; use a private test copy and confirm
source preservation, rendered text, table cells and PDF/PPTX revision parity. Compare native
page images with the original source, masking only intentionally changed content and slide
numbers. Render both sides using the same engine and version.

The optional image golden compares the approved light source against copied cover, org chart,
table, six-stop timeline, device mockups and closing slides. It masks only the renumbered footer,
allows a 24/255 channel difference and requires fewer than 0.01% changed pixels. Run it
separately from other desktop-render tests:

```sh
DEE_GOLDEN_TESTS=1 DEE_TEMPLATE_LIGHT=/local/official-light.pptx node --test native-golden.test.mjs
```
