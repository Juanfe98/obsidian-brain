# MVP Product Brief

Turn validated discovery or a clear product hypothesis into an MVP product brief.

Use this before Spec Kit. The goal is to define the product enough to create good requirements without overbuilding.

## Workflow

1. Read the product hypothesis, discovery notes, or user-provided context.
2. Define the target user and problem statement.
3. Define the Jobs To Be Done.
4. Map the MVP user journey.
5. Define in-scope and out-of-scope behavior.
6. Define success metrics and learning signals.
7. Identify product, UX, technical, business, and go-to-market risks.
8. Recommend whether the idea is ready for MVP requirements.
9. Do not create implementation tasks yet.

## Briefing Rules

- Be explicit about what will not be built.
- Keep the MVP focused on proving the core value.
- Include UX states that affect product value: empty, loading, error, success, first-use, repeat-use.
- Define success in observable terms.
- If the problem or user is still unclear, stop and recommend more discovery.

## Output

Return an MVP Product Brief:

1. Product summary
2. Target user
3. Problem statement
4. Jobs To Be Done
5. MVP goal
6. In scope
7. Out of scope
8. User journey
9. UX states
10. Success metrics / learning signals
11. Risks and open questions
12. Readiness verdict: Ready for MVP requirements / Needs discovery

## Optional Persistence

If the user asks to save the result, create or update:

```txt
product/mvp-brief.md
```

Ask before creating files unless the user explicitly requested persistence.
