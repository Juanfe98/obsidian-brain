# Product Idea Framing

Turn a vague product idea into a clear product hypothesis before engineering starts.

Use this when the user has an idea but has not yet defined the user, problem, value proposition, assumptions, or MVP direction.

## Workflow

1. Capture the raw idea in the user's words.
2. Identify the likely target user segment.
3. Clarify the problem and desired outcome.
4. Identify current alternatives or workarounds.
5. Draft a value proposition.
6. List riskiest assumptions.
7. Suggest the smallest MVP direction.
8. Ask focused follow-up questions for anything unclear.
9. Do not create engineering specs or implementation plans yet.

## Product Thinking Rules

- Start from the problem, not the feature.
- Be specific about the target user.
- Identify what users do today, even if the alternative is manual work or doing nothing.
- Separate facts from assumptions.
- Prefer learning and validation before implementation.
- Keep MVP scope small enough to test the core value.

## Output

Return a concise Product Hypothesis:

1. Raw idea
2. Target user
3. Problem statement
4. Current alternatives
5. Value proposition
6. Riskiest assumptions
7. MVP direction
8. Open questions
9. Recommended next step

## Optional Persistence

If the user asks to save the result, create or update:

```txt
product/product-hypothesis.md
```

Ask before creating files unless the user explicitly requested persistence.
