# TypeScript — Generics, Utility Types & Advanced Types

## Glossary

| Term | Meaning |
|------|---------|
| **Generic** | A placeholder type parameter that makes functions/types reusable across multiple types |
| **Type constraint** | Restricting a generic parameter with `extends`: `T extends string` |
| **Utility type** | Built-in TypeScript types that transform other types (`Partial`, `Pick`, `Omit`, etc.) |
| **Mapped type** | Creates a new type by transforming each property of an existing type |
| **Conditional type** | A type that resolves to different types based on a condition: `T extends U ? X : Y` |
| **`infer`** | Keyword used inside conditional types to extract and name a type |
| **Template literal type** | A type built from string patterns: `` `on${string}` `` |
| **`keyof`** | Produces a union of all keys of a type: `keyof User` → `"id" \| "name" \| "email"` |
| **`typeof`** | Infers the type of a value at the type level |
| **Index access type** | `T[K]` — accesses the type of a specific property |
| **Declaration merging** | TypeScript merges multiple declarations of the same interface name |

## Generics — reusable, type-safe code

### Basic generic function

```typescript
// Without generics — not reusable
function firstItem(arr: number[]): number { return arr[0]; }
function firstString(arr: string[]): string { return arr[0]; }

// With generics — one function, works for any type
function first<T>(arr: T[]): T {
    return arr[0];
}

const num  = first([1, 2, 3]);        // T inferred as number
const str  = first(["a", "b", "c"]); // T inferred as string
const user = first<User>([user1]);    // T explicitly provided
```

### Generic constraints — `extends`

```typescript
// T must have a .length property
function logLength<T extends { length: number }>(value: T): T {
    console.log(value.length);
    return value;
}

logLength("hello");        // ✅ string has .length
logLength([1, 2, 3]);      // ✅ array has .length
logLength(42);             // ❌ number has no .length

// Constrain by key — K must be a key of T
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
    return obj[key];
}

const user = { id: 1, name: "Juan", email: "j@test.com" };
getProperty(user, "name");   // ✅ returns string
getProperty(user, "age");    // ❌ "age" is not a key of user
```

### Generic interfaces and classes

```typescript
interface Repository<T> {
    findById(id: string): Promise<T>;
    findAll(): Promise<T[]>;
    save(entity: T): Promise<T>;
    delete(id: string): Promise<void>;
}

class UserRepository implements Repository<User> {
    async findById(id: string): Promise<User> { /* ... */ }
    async findAll(): Promise<User[]> { /* ... */ }
    async save(user: User): Promise<User> { /* ... */ }
    async delete(id: string): Promise<void> { /* ... */ }
}
```

## Utility Types — the most important ones

### Partial\<T\> — make all properties optional

```typescript
interface User {
    id: string;
    name: string;
    email: string;
    role: "admin" | "user";
}

type PartialUser = Partial<User>;
// { id?: string; name?: string; email?: string; role?: "admin" | "user" }

// Common use: update/patch functions
function updateUser(id: string, updates: Partial<User>): User {
    // Only the provided fields are updated
}
```

### Required\<T\> — make all properties required

```typescript
interface Config {
    timeout?: number;
    retries?: number;
    baseUrl?: string;
}

type StrictConfig = Required<Config>;
// { timeout: number; retries: number; baseUrl: string }
```

### Pick\<T, K\> — select specific properties

```typescript
type UserPreview = Pick<User, "id" | "name">;
// { id: string; name: string }
// Used for: DTOs, API responses that expose only some fields
```

### Omit\<T, K\> — exclude specific properties

```typescript
type CreateUserDTO = Omit<User, "id">;
// { name: string; email: string; role: "admin" | "user" }
// Used for: creation payloads (id is generated by DB, not provided by client)

type PublicUser = Omit<User, "email" | "role">;
// { id: string; name: string }
```

### Record\<K, V\> — dictionary/map type

```typescript
type UserByRole = Record<"admin" | "user" | "guest", User[]>;
// { admin: User[]; user: User[]; guest: User[] }

type CountByStatus = Record<string, number>;
// { [key: string]: number } — any string key, number value

// More precise than index signature — enforces specific keys
```

### Exclude\<T, U\> and Extract\<T, U\>

```typescript
type Status = "pending" | "active" | "inactive" | "deleted";

// Exclude — remove types from union
type ActiveStatus = Exclude<Status, "deleted" | "inactive">;
// "pending" | "active"

// Extract — keep only matching types
type TerminalStatus = Extract<Status, "inactive" | "deleted">;
// "inactive" | "deleted"
```

### ReturnType\<T\> and Parameters\<T\>

```typescript
async function fetchUser(id: string, includeRoles: boolean): Promise<User> {
    // ...
}

type FetchUserReturn = ReturnType<typeof fetchUser>;
// Promise<User>

type FetchUserParams = Parameters<typeof fetchUser>;
// [id: string, includeRoles: boolean]

// Practical: derive types from existing functions
type FetchArgs = Parameters<typeof fetchUser>[0]; // string (first parameter)
```

### Awaited\<T\> — unwrap Promise

```typescript
type ResolvedUser = Awaited<Promise<User>>;      // User
type DeepResolved = Awaited<Promise<Promise<User>>>; // User (unwraps recursively)

// Combine with ReturnType to get the resolved return type of an async function
type UserData = Awaited<ReturnType<typeof fetchUser>>; // User
```

### NonNullable\<T\>

```typescript
type MaybeUser = User | null | undefined;
type DefiniteUser = NonNullable<MaybeUser>; // User
```

## keyof and typeof operators

```typescript
// keyof — produces a union of an object type's keys
interface User { id: string; name: string; email: string; }
type UserKeys = keyof User; // "id" | "name" | "email"

// Use with generics for type-safe property access
function pluck<T, K extends keyof T>(objects: T[], key: K): T[K][] {
    return objects.map(obj => obj[key]);
}

const names = pluck(users, "name");   // string[]
const ids   = pluck(users, "id");     // string[]
pluck(users, "age"); // ❌ error — "age" is not keyof User

// typeof — infer type from a value (at the type level)
const defaultConfig = {
    timeout: 5000,
    retries: 3,
    baseUrl: "https://api.example.com",
};

type Config = typeof defaultConfig;
// { timeout: number; retries: number; baseUrl: string }

// Use case: derive a type from an existing object (no duplication)
function createConfig(overrides: Partial<typeof defaultConfig>): typeof defaultConfig {
    return { ...defaultConfig, ...overrides };
}
```

### Index Access Types — `T[K]`

```typescript
type UserEmail = User["email"]; // string

// Access nested types
interface Order {
    user: User;
    items: { id: string; quantity: number }[];
}

type OrderItem = Order["items"][number]; // { id: string; quantity: number }
type OrderUser = Order["user"]["name"];  // string
```

## Mapped Types

Transform each property of an existing type.

```typescript
// Basic mapped type — make every property optional
type Optional<T> = {
    [K in keyof T]?: T[K];
};
// Equivalent to Partial<T>

// Make every property readonly
type Immutable<T> = {
    readonly [K in keyof T]: T[K];
};
// Equivalent to Readonly<T>

// Make every property nullable
type Nullable<T> = {
    [K in keyof T]: T[K] | null;
};

// Remove readonly modifier
type Mutable<T> = {
    -readonly [K in keyof T]: T[K];
};

// Remove optional modifier
type Complete<T> = {
    [K in keyof T]-?: T[K];
};
// Equivalent to Required<T>

// Real-world: event handler map
type EventHandlers<T> = {
    [K in keyof T as `on${Capitalize<string & K>}`]: (value: T[K]) => void;
};

// EventHandlers<{ click: MouseEvent; focus: FocusEvent }>
// → { onClick: (value: MouseEvent) => void; onFocus: (value: FocusEvent) => void }
```

## Conditional Types

Types that resolve to different types based on a condition.

```typescript
// Basic conditional type
type IsString<T> = T extends string ? "yes" : "no";
type A = IsString<string>;  // "yes"
type B = IsString<number>;  // "no"

// Distributive conditional types — distributes over union members
type ToArray<T> = T extends any ? T[] : never;
type StrOrNumArray = ToArray<string | number>;
// → string[] | number[]  (not (string | number)[])

// Non-distributive — wrap in tuple
type ToArrayND<T> = [T] extends [any] ? T[] : never;
type Combined = ToArrayND<string | number>; // (string | number)[]

// Real-world: extract only function properties from a type
type FunctionProperties<T> = {
    [K in keyof T]: T[K] extends Function ? K : never;
}[keyof T];

type UserMethods = FunctionProperties<{ id: string; getName: () => string; getAge: () => number }>;
// "getName" | "getAge"
```

### `infer` — extract types from within conditionals

```typescript
// Extract the return type of a function
type ReturnTypeOf<T> = T extends (...args: any[]) => infer R ? R : never;
type StringReturn = ReturnTypeOf<() => string>; // string

// Extract the element type of an array
type ElementType<T> = T extends (infer E)[] ? E : never;
type StringElement = ElementType<string[]>; // string
type UserElement   = ElementType<User[]>;   // User

// Extract the resolved type of a Promise
type UnwrapPromise<T> = T extends Promise<infer R> ? UnwrapPromise<R> : T;
type Resolved = UnwrapPromise<Promise<Promise<string>>>; // string

// Extract first parameter type
type FirstParam<T> = T extends (first: infer F, ...rest: any[]) => any ? F : never;
type First = FirstParam<(name: string, age: number) => void>; // string
```

## Template Literal Types

Build string union types from patterns.

```typescript
type Verb = "get" | "post" | "put" | "delete";
type Resource = "user" | "order" | "product";

// All combinations
type RouteHandler = `${Verb}${Capitalize<Resource>}`;
// "getUser" | "getOrder" | "getProduct" | "postUser" | ... (12 combinations)

// Event names
type EventName<T extends string> = `on${Capitalize<T>}`;
type ClickEvent  = EventName<"click">;   // "onClick"
type SubmitEvent = EventName<"submit">;  // "onSubmit"

// CSS property getter/setter pattern
type CSSPropertyGetter = `get${Capitalize<keyof CSSStyleDeclaration & string>}`;

// Real-world: typed event emitter
type EventMap = {
    userCreated: { id: string; name: string };
    orderPlaced: { orderId: string; amount: number };
    paymentFailed: { error: string };
};

// "on" + event name = handler name
type Listeners = {
    [K in keyof EventMap as `on${Capitalize<K & string>}`]: (event: EventMap[K]) => void;
};
// { onUserCreated: (e: {...}) => void; onOrderPlaced: ...; onPaymentFailed: ... }
```

## Declaration Merging & Module Augmentation

```typescript
// Augmenting an existing interface (adds properties to existing type)
interface Window {
    analyticsTracker: { track: (event: string) => void };
}

// Now TypeScript knows about your custom property
window.analyticsTracker.track("page_view"); // ✅

// Augmenting a module (adding types to a third-party library)
declare module "express" {
    interface Request {
        user?: { id: string; email: string; role: string };
    }
}

// Now req.user is typed in Express route handlers
app.get("/me", (req, res) => {
    const user = req.user; // ✅ typed as { id, email, role } | undefined
});
```

## tsconfig — strict flags that matter

```json
{
    "compilerOptions": {
        "strict": true,                       // enables all strict checks below

        "noImplicitAny": true,                // error on implicit any
        "strictNullChecks": true,             // null/undefined are not assignable to other types
        "strictFunctionTypes": true,          // stricter function parameter checking (contravariance)
        "strictPropertyInitialization": true, // class properties must be initialized in constructor

        "noUncheckedIndexedAccess": true,     // T[string] returns T | undefined (not just T)
        "exactOptionalPropertyTypes": true,   // { a?: string } ≠ { a: string | undefined }

        "noImplicitReturns": true,            // all code paths must return a value
        "noFallthroughCasesInSwitch": true,   // switch cases must have break/return
    }
}
```

### noUncheckedIndexedAccess — catches a common bug

```typescript
const users: { [key: string]: User } = {};

// Without noUncheckedIndexedAccess:
const user = users["unknown"]; // type: User — but actually undefined at runtime!
user.name; // runtime crash

// With noUncheckedIndexedAccess:
const user = users["unknown"]; // type: User | undefined — forces you to check
user?.name; // ✅ safe
```

## Interview answers

### What are generics and why are they useful?
Generics are type parameters that make functions, classes, and interfaces reusable across different types without sacrificing type safety. Instead of writing separate functions for each type, you write one generic function and let TypeScript infer the type — or provide it explicitly.

### What is the difference between Pick and Omit?
`Pick<T, K>` creates a type with only the specified properties from T. `Omit<T, K>` creates a type with all properties of T except the specified ones. Use Pick when you want a small subset; use Omit when you want most properties except a few.

### What is a mapped type?
A type that creates a new type by iterating over the properties of an existing type and transforming them. `{ [K in keyof T]: ... }` is the syntax. This is how built-in utilities like `Partial`, `Readonly`, and `Record` are implemented.

### What is the `infer` keyword?
Used inside conditional types to extract and name a type from within another type. For example, `T extends Promise<infer R> ? R : T` extracts the type that a Promise resolves to, and calls it `R`. Without `infer`, you can't name the matched type to use it in the result.

### What is the difference between Exclude and Omit?
`Exclude<T, U>` works on **union types** — removes union members assignable to U. `Omit<T, K>` works on **object types** — removes properties named K from object type T. Common confusion: `Exclude` is for unions, `Omit` is for object properties.

### What does strictNullChecks do?
Without it, `null` and `undefined` are assignable to any type — a common source of runtime crashes. With it, `null` and `undefined` are their own types and must be explicitly handled. This is the single most impactful TypeScript option for catching real bugs.
